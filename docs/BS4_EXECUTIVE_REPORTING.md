# BOP SOCIAL — EXECUTIVE REPORTING & PDF EXPORT ENGINE (PHASE BS-4G)
*Document Version: 1.0.0 · Phase BS-4G Approved Architectural Specification*

---

## 1. Executive Overview

Phase **BS-4G** establishes the canonical, deterministic Executive Reporting & PDF Export Engine for Bop Social. It synthesizes normalized timeseries rollups (`SocialMetricRollup`), content snapshots (`SocialMetricSnapshot`), and persisted Business Intelligence signals (`BusinessSignal`) into professional, audit-defensible, client-facing executive reports.

### Core Architectural Axioms
1. **Deterministic First**: Every figure, delta, indicator, and conclusion originates directly from verified database records.
2. **Zero Generative AI**: No LLM narrative, automated hallucinations, or synthetic numbers exist in this phase.
3. **No Fake Zeros**: Unsupported or unavailable metrics (such as Instagram `SHARES` or `REACH` under PARTIAL capability mode) are explicitly presented as unavailable—never replaced with `0`.
4. **Strict Metric Aggregation Semantics**:
   - `FOLLOWERS_TOTAL`: Treated strictly as a point-in-time state gauge (latest observation), never summed.
   - `REACH`: Computed as average daily reach; never summed across calendar days to prevent audience inflation.
5. **Deterministic Source Traceability (`source_hash`)**: Every report calculates a cryptographic SHA-256 digest of input parameters and source records, ensuring reproducibility.
6. **Server-Side Print Quality**: Professional A4 PDF generation powered by WeasyPrint and inline vector SVGs, with clean page breaking, headers, and running footers.

## 3. Structured Report Payload Schema (`report_data`)

The payload generated by `build_executive_report_data` comprises 12 distinct sections:

1. **`metadata`**: Technical context (`template_version`, `source_hash`, `source_rollup_count`, `source_signal_count`, `generated_at`, `language`, `report_type`).
2. **`cover`**: Client name (internal IDs never leaked), formatted period label, localized subtitle, and platform scope.
3. **`executive_summary`**: 3 to 5 deterministic bullet points derived strictly from data facts (follower trends, post volume, capability modes, business signal count, and statistical sufficiency notes).
4. **`kpi_overview`**: Candidate metrics (`FOLLOWERS_TOTAL`, `FOLLOWERS_NET_CHANGE`, `ENGAGEMENT_TOTAL`, `REACTIONS`, `COMMENTS`, `SHARES`, `VIDEO_VIEWS`, `PROFILE_VIEWS`, `REACH`) comparing current period to the preceding equal-duration baseline window (`absolute_delta`, `relative_delta`, `delta_display`, `is_gauge`, `is_non_aggregatable`, `unavailable_reason`).
5. **`performance_trends`**: Daily timeseries data points formatted for sparklines and timeseries review.
6. **`content_performance`**: Top-performing posts in the window, attributing platform format (`IMAGE`, `VIDEO`, `CAROUSEL_ALBUM`), reactions, comments, shares, and Bop Social authorship.
7. **`platform_breakdown`**: Individual cards for Facebook (`FULL`) and Instagram (`PARTIAL`), enumerating available vs. unavailable metrics.
8. **`business_intelligence_signals`**: Integrates active `BusinessSignal` records, preserving `PROVIDER_PARTIAL` and `INSUFFICIENT_SAMPLE` as critical business findings.
9. **`winning_formats`**: Evaluates format cohorts against statistical medians ($n \ge 3$). If sample is inadequate, renders explicit insufficient data notice.
10. **`posting_time_insights`**: Daypart optimization based on client timezone. Renders explicit insufficient data state if sample is small.
11. **`data_health`**: Overall pipeline freshness and capability states.
12. **`methodology`**: Client-facing explanations of median comparisons, confidence calibration, unavailable metric policy, and reach non-aggregatability.

## 4. Source Hash Specification (`source_hash`)

The `source_hash` is computed as:
$$\text{source\_hash} = \text{SHA256}(\text{client\_id} \mid \text{start\_date} \mid \text{end\_date} \mid \text{platform} \mid \text{language} \mid \text{template\_version} \mid \text{rollup\_count} \mid \text{signal\_identities})$$

Identical input parameters against identical source records yield identical source hashes, ensuring end-to-end auditability.

## 5. Server-Side PDF Architecture (WeasyPrint)

- **Renderer**: WeasyPrint 60.2 with pinned `pydyf==0.10.0`.
- **Cache Environment**: `XDG_CACHE_HOME=/tmp` ensures Fontconfig operates silently and deterministically in unprivileged Docker containers.
- **Visual Palette**:
  - Primary Dark: `#1E202A` (Bop Charcoal)
  - Accent Gold: `#F5A623` (Bop Gold)
  - Accent Cyan: `#00D7FF` (Bop Cyan)
  - Card Background: `#FFFFFF`
  - Border: `#E2E8F0`
- **Charts**: Rendered as inline vector SVGs directly embedded in the HTML stream—eliminating headless browser dependencies and client-side canvas capture flakiness.
- **Storage**: Persisted securely in Django `MEDIA_ROOT/reports/executive/%Y/%m/`. Never exposed via public unauthenticated links.

All endpoints inherit from `AnalyticsBaseView` and enforce strict tenant isolation:

| :--- | :--- | :--- |

| `POST` | `/api/analytics/reports/<id>/pdf/` | Compiles server-side PDF, calculates SHA-256 checksum, and saves file. |
| `GET` | `/api/analytics/reports/<id>/download/` | Authenticated streaming download of the PDF binary. |
| `DELETE` | `/api/analytics/reports/<id>/` | Deletes report and media file without modifying source analytics. |

## 7. Tenant Isolation & Security

1. **Client Scoping**: Users can only generate, list, view, and download reports belonging to clients they own (`owner_user=request.user`), unless possessing `is_staff` privileges.
2. **Download Protection**: `/download/` validates tenant ownership before opening the file stream, returning `404` for unauthorized cross-tenant requests.
3. **No Credential Decryption**: Reporting queries use `.defer("access_token", "refresh_token")` on `PlatformCredential`, ensuring Fernet encrypted tokens are never decrypted during analytics or reporting operations.

## 8. Future AI Boundary (BS-4H)

- **Phase BS-4G Scope**: Complete deterministic structured report builder, deterministic template copy, i18n dictionaries, WeasyPrint PDF compiler, and frontend management interface.
- **Phase BS-4H Boundary**: Any future narrative AI or LLM summary generation must strictly consume verified `report_data` JSON (or `BusinessSignal` evidence) as grounded context. The LLM must never query unrestricted provider APIs or generate ungrounded statistics. BS-4G establishes the prerequisite structured substrate for that boundary.
