# BOP SOCIAL — PHASE BS-3F: INSTAGRAM VIDEO STORY PILOT & HARDENING

## 1. Executive Summary & Context

Phase **BS-3F.6B** executed the authorized live publication pilot for **UnifiedPost #7** on Instagram account `@bopsoluciones` (`17841464843082253`) reusing video **`MediaAsset #5`** (MP4, 720x1280, 10.005s, H.264/AAC).

The pilot revealed a subtle routing defect:
- The post was authored as an Instagram Video Story (`media_type='story'`).
- However, the live payload sent to Meta Graph API was `{'media_type': 'STORIES', 'image_url': <s3_url>}` instead of `video_url`.
- Meta Graph API accepted the URL and generated an **Image Story** (still frame ingestion), returning media ID `17950578426324070` (`media_product_type: 'STORY'`, `media_type: 'IMAGE'`).
- The pilot completed without exceptions, but produced an Image Story instead of the intended Video Story.
- In **BS-3F.6C**, the defect was audited, isolated, and permanently hardened across both the publisher and orchestrator layers.

---

## 2. Root Cause Analysis

### Defective Legacy Routing
In `backend/social_stats/publishers/instagram.py`, `publish_story` contained fallback inference:
```python
media_type = (kwargs.get('media_type') or '').upper()
if not media_type:
    media_type = 'VIDEO' if str(media_url).lower().endswith(('.mp4', '.mov', '.webm')) else 'IMAGE'
```

Two compounding failures occurred:
1. **Orchestrator Omission**: `_dispatch_publish` in `backend/social_stats/orchestrator.py` called `publisher.publish_story(credential, first)` without passing any `media_type` or MIME metadata.
2. **Presigned S3 URL Suffix Failure**: Provider URLs generated by `media_service` are AWS S3 SigV4 presigned URLs:
   `https://bucket.s3.amazonaws.com/.../video.mp4?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Signature=...`
   Because `str(media_url)` ends with the SigV4 query string, `str(media_url).lower().endswith(...)` evaluated unconditionally to `False`.

Consequently, `media_type` fell back to `'IMAGE'`, setting `data['image_url'] = media_url`, bypassing container readiness polling, and creating an Image Story on Meta.

## 4. Hardened Architecture (BS-3F.6C)

### A. Canonical Media Kind from MediaAsset MIME
Canonical media kind (`IMAGE` vs `VIDEO`) is now derived strictly from authoritative database metadata (`MediaAsset.mime_type`):
- `mime_type.startswith('video/')` $\to$ `VIDEO`
- `mime_type.startswith('image/')` $\to$ `IMAGE`
- Any unsupported MIME type raises a controlled `PublishError(code='unsupported_media_type')`.

### B. Explicit Orchestrator Propagation
In `backend/social_stats/orchestrator.py`:
- `_resolve_story_media_kind(post, raw_urls)` inspects the linked `MediaAsset` for the post.
- `_dispatch_publish` enforces multiple-asset safety (exactly 1 media item for Story).
- `publisher.publish_story(credential, first, media_type=media_kind, media_kind=media_kind)` explicitly forwards the authoritative kind.

### C. Resolution Priority in `InstagramPublisher.publish_story`
1. **Explicit normalized keyword argument**: `media_kind` or `media_type` (`IMAGE` or `VIDEO`).
2. **Trusted MIME hint**: `mime_type` keyword argument if provided.
3. **Safe Legacy URL Path Fallback**: Uses `urllib.parse.urlparse(media_url).path.lower()`, stripping query parameters completely before checking extension (`.mp4`, `.mov`, `.webm` $\to$ `VIDEO`; `.jpg`, `.jpeg`, `.png` $\to$ `IMAGE`). Unrecognized extensions raise controlled `PublishError(code='unsupported_media_type')`.

### D. Payload & Polling Contracts
- **IMAGE Story**:
  - Payload contains `media_type='STORIES'`, `image_url=<url>`.
  - Excludes `video_url`, `caption`, `share_to_feed`.
  - Polling: bypassed (immediate publish).
- **VIDEO Story**:
  - Payload contains `media_type='STORIES'`, `video_url=<url>`.
  - Excludes `image_url`, `caption`, `share_to_feed`.
  - Polling: enforced (`_wait_for_container_ready` polls until `FINISHED`).

### E. Post-Publish Provider Verification & Mismatch Semantics
In `_publish_container`:
- Fetches `permalink,media_type,media_product_type` from Meta Graph API.
- If provider returns `media_type` that does not match requested `expected_media_type`:
  - Preserves `platform_post_id` and `platform_url` (recording live occurrence).
  - Flags `mismatch = True` in `raw_response`.
  - Records `error_code = 'provider_media_type_mismatch'`.
  - Records descriptive `error_message`.
  - Log status remains `'success'`, ensuring parent post transitions to `'published'` via `update_unified_post_status`.

### F. No Automatic Retry Invariant
Because the story was already physically published by the provider, marking the post or log as failed could trigger automatic republishing workers or manual retry clicks that create duplicate stories. Setting `UnifiedPost` to terminal `'published'` with visible mismatch error fields prevents retries while alerting operators.
